# 产品上下文（Product Context）

> 本文件回答「这个 Skill 服务于什么产品、什么人、什么业务」。生成任何页面前先读这里，再读 `design-principles.md`、`components/README.md`、`pages/README.md`。
> 这里只写**已确认的产品事实**；未在需求输入中给出的字段、校验、上限一律标「待确认」，不得自行补成事实。

## 一、产品定位

海外版「访客预约」前端原型，服务海信海外园区（泰国 / 越南等）的访客进出管理。交付物是 **375px 手机端前端 mock 原型**（Vue 3 + Vite 5 + Vant 4 + vue-router 4 + vue-i18n），包含页面、路由、组件调用与本地资源。

**不是**：数据库、服务端 API、后端鉴权、真实扫码 / 二维码服务、真实短信 / 审批流、生产部署配置。

## 二、角色与端

| 端 | 角色 | 在本原型里做什么 |
|---|---|---|
| 用户端（主访客） | 访客本人 | 填写预约信息、登记本人身份、添加同行人与车辆、同意三项协议、确认提交、查看预约记录 / 详情 / 通行凭证 |
| 用户端（同行人） | 受邀人员 | 接收邀请、查看凭证（原型中为 mock 展示） |
| 安保端 | 门岗 / 安保 | 搜索预约、查看预约详情、核验通行凭证、登记出入 |
| 审批端 | 被访人 / 审批人 | 审批记录（原型中以记录卡与时间线展示，不实现真实流转） |

## 三、主流程（新建预约，三步）

```text
第 1 步 预约信息    园区 / 日期 / 公司 / 部门 / 来访类型 / 事由 / 被访人电话 + 三项协议勾选
   ↓ 点「下一步」：先校验必填，再校验未勾选项；「同意并继续」勾选未选项并进入第 2 步
第 2 步 访客信息    照片上传 / 姓名 / 电话 / 证件类型 / 证件号 / 境外人员补充说明
                    + 同行人卡片（UserCard）+ 车辆卡片（VehicleCard）
   ↓
第 3 步 确认信息    只读汇总：业务信息 / 访客信息 / 同行人 / 车辆
   ↓ 提交
提交成功 → 审批中 → 已通过 → 通行凭证 → 安保核验 → 出入记录
```

**第一步校验的既有口径（2026-11-12 用户裁决）**：

- 三项协议初始均未勾选，只弹「未勾选 / 未填写」的项，已勾选的不提示；
- 协议确认 `Dialog`：左「返回」、右「同意并继续」；协议名 `#00AAA6` 可点击打开对应 `Popup`；
- Popup 内「我已阅读…」按钮勾选对应协议并关闭弹层；
- 「同意并继续」勾选未选项并跳到第 2 步。

**第二步添加的既有口径**：`UserCard` / `VehicleCard` 的「保存并继续」不关闭弹层、清空输入、重新 focus 输入框（键盘保持唤起）；按钮区 `@mousedown.prevent` 防止抢焦点；添加按钮无加号图标（按 11-11 用户截图裁决）。

## 四、业务对象与字段

| 对象 | 典型字段 | 备注 |
|---|---|---|
| 预约 | 园区、拜访日期、来访公司、部门、来访类型、事由、被访人电话 | 园区用 `Cascader`（园区 → 门两级）；日期用 `DatePicker` |
| 主访客 | 照片、姓名、电话（带区号）、证件类型、证件号、境外人员补充说明 | 全部用 `Field`；照片用 `Uploader` |
| 同行人 | 姓名列表 | 用 `UserCard`；组件内默认最多展示 5 个，其余进 `PersonListPopup` |
| 车辆 | 车牌列表 | 用 `VehicleCard`；编辑 / 删除交互由组件提供 |
| 协议 | 《访客须知》《隐私政策》《个人信息收集、使用及披露同意书》 | 用 `Checkbox` + `Dialog` + `Popup` 组合 |
| 预约记录 | 状态、编号、时间、访客、来访单位 | 用 `AppointmentRecordCard`，状态胶囊复用 `InlineInput` |

**⚠️ 字段、校验规则、数量上限、正则一律来自 `requirements-input.md` 的本次需求输入。** 2026-11-13 跨模型实测中，曾有产物自行编造「同行人最多 50 人」「车辆最多 10 辆」「姓名 2–50 字符」「车牌 12 字符」并写成 i18n 文案与校验逻辑 —— 这类**未确认规则写成事实**是被禁止的。需求没写，就只做输入与展示，不加上限提示。

## 五、国家版本与多语言

- Figma 里 4 组同名业务页面是**分属不同国家的有效版本**，不合并、不去重、不排优先级（用户 2026-11-05 / 11-06 裁决）；生成时以当前 `pages:` 输入为准。
- 工程实际三语：`zh` / `en` / `th`（`src/i18n.js`）；`references/runtime-conditions.md` 提到的越南语为早期规划，未落地。
- **可变文案一律换行**，不允许截断、省略号、隐藏或溢出屏幕（用户 2026-11-12 裁决）。泰语 / 英语长文案尤其要验证两行、三行场景。
- 长弹层标题同样换行，不能被右上关闭按钮遮挡。

## 六、数据边界

一律 mock 数据。不写真实个人信息、API Key、生产数据；不写死国家字段组合；不依赖个人绝对路径或临时 Figma URL。
