# 设计原则与交互规则（Design Principles）

> 本文件是**跨页面、跨组件**的设计原则与冻结口径，是接需求后的第一道约束。每条原则都给出「判据」，便于人工核对与 `npm run gate` 脚本判定。
> 逐组件 API 见 `components/README.md`；逐页面模式见 `pages/README.md`；精确数值见 `design-tokens.md` / `design-spec-from-figma.md` 第九节。

## 一、总纲：复用优先，不重新还原设计稿

> 用户 2026-11-12 裁决：「我搭建出模板和组件是希望接到需求后识别到已有页面或者符合直接调用，而不是去设计稿取精确数值」。

**模板 + 组件库是为了复用，不是为了每次重新还原设计稿。** 组件内部的视觉（尺寸、间距、字号、图标、颜色）是**已冻结的资产**，不是每轮需求都要重新去 Figma 取一遍数值再改一次。

### 接需求的标准顺序

1. 先查 `src/pages/` 有没有对应页面、模板工作台有没有对应卡片，再查 `components/README.md` / `component-registry.md` 第二节有没有对应组件；
2. **命中 → 只写组装层**：在页面里放组件、传 prop、给数据；组件内部一律不动；
3. 组件能力不够 → 优先用现有 prop；确实缺能力才补**最小**的那个 prop，不顺手重画视觉；
4. **只有两种情况才去 Figma 取精确数值**：① 首次沉淀一个全新组件 / 全新页面；② 用户明确说「按设计稿校准」或给了截图且要求逐像素对齐。其余一律不去；
5. 用户给了截图就按截图裁决，截图与 Figma 冲突时不再翻 Figma 争论，一句话说明差异即可。

**判据**：一轮需求里，若改了 `src/components/figma/` 下组件的内部样式、或调用了 Figma REST API 取数值，必须属于上述两种情况之一，否则视为绕路。

> 反面案例（2026-11-11）：需求只是「新建预约访客信息加同行人 / 车辆卡片并撑满」，组件和页面都在，却跑去 Figma `1087:25278` 取一整套数值、改 `ListCard` 内部间距和按钮字号、给组件加 3 个 prop、连带改另外两个页面。按总纲应只动 `AppointmentFormPage.vue`。

## 二、组装层优先：定位到页面位置直接加

> 用户 2026-11-11 裁决：「人员和车辆的卡片都是有的，新建页面也是有的，我的理解是定位到页面位置直接添加就好，现在反而绕了一大圈」。

- 「组件已有 + 页面已有 → 改一处」的需求，**默认只动目标页面 1 个文件**；能删几行 CSS 解决的，不要新增组件调用、不要加 prop、不要顺手改组件内部视觉。
- 诊断是必要的（组件可能已存在但被页面 CSS 隐藏 / 撑满规则失效），但**到此为止**；发现同类问题在别的页面，记下来、等用户决定，不要顺带清干净。
- 上一轮刚定的规则（如「页面不得覆盖组件布局」）是**约束不是任务**；遇到旧写法不必当轮全部整改。
- 扩面（改组件 API / 动其它页面 / 重打 zip / 全套回归）前先问一句，或至少在回复里说明「我多做了什么、可回退」。

## 三、组件能力不够或未覆盖 → 先问、等裁决、给交互方案

> 用户 2026-11-13 裁决。

命中「组件缺这个能力 / 注册表里没有这个组件」时，不得直接扩通用组件、自造页面结构、或用临时 HTML / 页面 CSS 绕过。必须先输出：

1. 缺的是什么能力、命中哪个组件 / 哪个 prop；
2. **2–3 个可行的交互方案**，各自说明改哪些文件、对现有页面与组件的影响、是否符合多语言换行 / 长标题 / 弹层底色等既有口径；
3. 推荐方案与理由。

**等用户明确裁决选一个后才动手**；裁决后仍优先用现有 prop，确实缺才补最小 prop。

当前登记在案的能力缺口：`Field` 只读态单行 `<input>` 无法换行（顶部园区名换行仍待裁决）、`CollapseItem` / `FieldCheckbox` / `ScanFrame` 未沉淀、`IconBox` 图标集待补。

## 四、视觉与组件复用

| # | 原则 | 判据 |
|---|---|---|
| P1 | Figma 组件是视觉唯一来源；Vant 只提供行为，不使用默认 Vant 视觉 | 页面 / 组件里无裸 `van-*` 默认外观承担视觉 |
| P2 | 页面必须调用已注册组件，禁止用原生 HTML 或自绘结构替代 | `npm run gate` 的「组件复用」项通过 |
| P3 | 每个组件绑定 Figma Node ID，且必须带「所在页面 > 位置 > Figma 名称」，禁止只写裸 `数字:数字` | 查 `figma-node-index.md`，查不到标「待确认」 |
| P4 | 禁止「类推」与「默认值填空」：组件落地前逐属性读 Figma，实测用 `getBoundingClientRect` + `getComputedStyle` 回读，差值 > 1px 不通过 | 登记到 `component-fidelity-checklist.md` |
| P5 | 组件名全量去掉 `Figma` 前缀；CSS 类名 `figma-*`、目录 `components/figma/`、画布类 `.figma-phone` 保留 | 命名核对 |
| P6 | 必须使用本地 `src/assets/` 资源，禁止字符 / 默认图标替代 Figma 资源 | 资源索引见 `assets/README.md` |
| P7 | 页面范围限 375 手机画布，禁止横向滚动；所有页面 `scrollWidth == clientWidth` | 浏览器实测 |
| P8 | 组件、页面模板、业务页面并行维护；组件与页面是一对多复用，不是一个页面一个组件 | 无重复实现 |

## 五、页面不得覆盖组件布局模型（规则 11 / 12）

> 起因：安保端详情页写 `.sd-tabs { display:block }`，把 `Tabs` 内部的 `display:flex` 静默顶掉，三个页签退回 72px 挤在左边。

组件根元素的 class 会与页面传入的 class **合并**，页面 scoped 样式与组件 scoped 样式特异性相同，打包后**谁声明在后谁生效**。因此：

- 页面**禁止**覆盖组件的 `display` / `flex` / `grid` / `position` / `float` 以及组件的 `padding`；
- **固定尺寸与底色**（`width` / `height` / `background`）也必须走 prop，不得在页面写死；
- 唯一允许的例外是「容器内自适应」的 `:deep(.x) { width: 100% }`（组件没有满宽 prop 时让它在卡片里铺开，不改变组件内部布局）；
- 组件缺 prop 时，**先给组件补 prop 再调用**；组件把「页面可调的外观」收敛成 prop 并在注册表 2.0 备注（参考 `Tabs` 的 `full` / `height` / `background`、`ListCard` 的 `full` / `padding` / `addIcon`）。

## 六、多语言与长标题：一律换行

> 用户 2026-11-12 裁决：「切换为多语言如果不允许截断或者隐藏，超出屏幕；可以进行换行多语言策略」。

- 可变文案（尤其泰语 / 英语长文案）**一律换行**，不允许截断、省略号、隐藏或溢出屏幕；
- 组件里**禁止**给 i18n 文案写 `white-space:nowrap + text-overflow:ellipsis + overflow:hidden` 三件套；需要单行省略的只限「姓名 / 值」这类有界数据，且要显式说明；
- 正确写法：`white-space:normal; overflow-wrap:anywhere; word-break:break-word`；勾选框 `align-self:flex-start` 保持首行对齐；
- **长弹层标题一律换行**，不允许截断、省略号或被右上关闭按钮遮挡：`Popup.vue` header 用 `min-height` + 左右 60px 安全内边距，`h2` 显式换行；
- 三语 `zh` / `en` / `th` 同一组 key 齐全，缺一个就会在控制台出现 `vue-i18n missing key`。

## 七、弹层与协议交互

> 用户 2026-11-12 澄清：「背景是 F2F3F5，内容卡片是白底」。

- 底部 `Popup` / `LanguagePopup` / `MemberSelectionFlow` / `PersonListPopup` 外层背景 `#F2F3F5`，内部内容卡片（`.agreement-card` / `.list` / `.member-popup__list`）白底 `#FFFFFF`；
- 居中 `Dialog` 与日历 / 级联保持组件内白底，**不再全局强制 `van-popup` 根白底**；
- 协议确认 `Dialog` 按钮顺序：左「返回」、右「同意并继续」；
- 协议名称统一 `#00AAA6` 且可点击打开对应 `Popup`；
- Popup 内「我已阅读…」按钮会勾选对应协议并关闭弹层；
- 弹层统一经 `usePopupTeleport()` 挂进 `.figma-phone` 375 画布，不相对桌面视口居中；
- 关闭按钮 `×` 放**右侧**且用 flex 居中，不用文字 `×` + `line-height`。

## 八、结果级约束（生成产物必须满足）

> 这一节是 2026-11-13 跨模型实测后新增：仅有「先读什么」的过程约束不够，跳过后没有代价，必须规定**结果里必须有什么**。

1. **产物形态**：必须是可运行的 Vue 3 + Vite 工程，从 `templates/project-starter/` 复制；**禁止用纯单文件原生 HTML 替代 Skill 的组件库工程**。
2. **必用组件核对表**：按 `components/README.md` 第六节逐场景核对，缺一项即不合格。
3. **确认页只读字段**：必须 `Field state="readonly"` 的**上下结构**（标题在上、值在下）；**禁止** `.row__label` 左 + `.row__value` 右的两列键值行。
4. **同行人 / 车辆**：必须用 `UserCard` / `VehicleCard`（基于 `ListCard`）；禁止自绘 `.tags` / `.tag` / `.vehicles` / `.vehicle` / `.addbtn`；添加按钮无加号。
5. **不得把未确认的业务规则写成事实**：数量上限、字符长度、车牌规则等只来自需求输入。
6. **不得自造结构**：禁止 `document.createElement` 手拼业务列表、自绘 form-sheet 添加弹层、自绘 checkbox / popup / dialog。
7. **组件交互必须保留**：点击、回填、弹层、选中态、删除 / 清空、保存并继续保持聚焦，不能当静态图。

`npm run gate` 是可执行判定；未通过项如实标注，不写成已完成。

## 九、需求与产物纪律

- 需求未确认前不生成页面代码；需求已按 `requirements-input.md` 结构化输入后，按决策树 + SOP 生成；
- 待确认项标「待确认」，不推测、不补成事实；
- 一律 mock 数据，不写后端请求、不写个人绝对路径或临时 Figma URL；
- 涉及视觉或代码的改动，先在组件预览页经用户确认后再提交推送；
- **发布授权不跨轮**：用户说「先不着急发布，我先在本地测试好」后，本轮及后续只做本地验证与打包，不主动发布。
