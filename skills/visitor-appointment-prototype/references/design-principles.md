# 设计原则与交互规则（Design Principles）

> 访客预约原型的设计原则与交互规则。

## 一、视觉主线

- **一条主视觉谱系**：青绿主题（`#22BBB3` 主色）贯穿标题渐变、主按钮、选中态、强调元素。
- 辅助谱系：仅用状态色（成功绿/警示橙/错误红/中性灰）区分状态，不引入额外装饰性色彩。
- 无装饰性渐变堆叠；渐变仅用于页面顶部标题区（primary-5 → primary-6）。

## 二、布局原则

| 原则 | 说明 |
|---|---|
| 移动端优先 | 375pt 单列布局 |
| 页面边距 | 左右各 16px，内容宽 343px |
| 卡片内边距 | 16px，卡片内容宽 311px |
| 间距 | 统一 4 的倍数（4/8/12/16/20/24） |
| 长表单收敛 | 用分段 Tab（预约信息/访客信息/证件照片）或步骤条收敛 |

## 三、层级与信息架构

1. 页面大标题（24px Bold）→ 区块标题 → 表单标签 → 输入内容/占位（16px）→ 辅助信息（14px）→ 错误提示（12px）。
2. 信息分组用卡片容器（圆角 12px）+ 区块标题组织。
3. 状态用标签（Tag）表达，不用纯文字颜色区分。

## 四、交互规则

### 4.1 反馈
- 每个可点击控件都有明确反馈（按钮按下态、选中高亮、加载态）。
- 操作结果即时反馈：提交成功页（对勾 + 预约号）、错误提示（12px 红字）。

### 4.2 焦点与键盘
- 输入框聚焦时主色边框/高亮。
- 数字输入用数字键盘（van-number-keyboard）。

### 4.3 触摸目标
- 所有可点击控件 ≥ 44px 高度。

### 4.4 状态覆盖
每个组件需覆盖：默认、聚焦/激活、选中、禁用、加载、成功、错误、空状态。

## 五、组件分层规则

| 层 | 定义 | 示例 |
|---|---|---|
| 通用组件 | Vant 基础组件 | Field、Button、Popup、Search、Picker |
| 业务组件 | 业务语义组件 | 审批记录卡片、工单信息卡片、动态卡片 |
| 页面模板 | 通用/业务组件拼装 | 新建预约表单、详情页、出入登记列表 |

> **核心原则**：弹窗、复合控件不单独列为组件，由基础组件（Popup + Field + Button 等）在页面层拼装，组合关系记录在 `components.md` 的「组合规范」一节。

## 六、可访问性

- 文字对比度：正文满足 WCAG AA（主文字 #1D2129 对白底）。
- 状态不只靠颜色表达：状态标签同时有文字（如「已通过」「审核中」）。
- 必填项用 `*` 明确标记。

## 七、多语言

- 四语（中文、英文、泰语、越南语），文案走 i18n。
- 默认显示中文，右上角按钮显示当前语言，默认 `CN`。
- 点击语言按钮打开语言选择弹层，支持 `CN / EN / TH / VN` 并显示当前选中态。
- 语言切换与字段配置解耦，字段由本次需求输入决定。
- 原型不实现 Figma 中的浏览器状态栏、地址栏和底部浏览器工具栏；这些只作为设计稿参考。
- 错误提示显示在对应字段下方；错误状态不改变字段边框颜色。
