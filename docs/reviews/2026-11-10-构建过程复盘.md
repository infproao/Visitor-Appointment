## 三、清单里没有的 6 条

### 3.1 硬约束只写在文档里，没有执行机制（最根本）

`AGENTS.md` 写着"颜色只认 token"，实际 721 处裸值、5 处 `var()`——规则执行率约 0.7%。
"每个 Node ID 必须带页面 > 位置 > 名称"——22/44 组件一个都没有。
"行高写 px"——2 处无单位。

**这不是态度问题，是规则形态问题。**写在文档里的约束靠人记，记不住就漂；写在命令里的约束会报错，报错就得修。
你们已经把"该怎么做"写到了极致（`design-spec-from-figma.md` 69KB、`component-registry.md` 52KB），缺的是**一个会失败的检查**。

### 3.2 事实源分裂成五处

同一组数值同时存在于：
1. `references/design-spec-from-figma.md`（69KB，标注"渲染口径"）
2. `references/design-tokens.md`（9KB）
3. `references/component-registry.md`（52KB，22 组件权威清单）
4. `DesignSpecPanel.vue`（24KB，**157 个裸 hex**）
5. `theme.css`（33 个 token）

已经出现补丁式规则："与 `design-tokens.md` 冲突时以此为准"。**出现"以哪份为准"这句话，就是分裂的证据。**
更麻烦的是第 4 处：一个"设计规范展示面板"把值抄进了 Vue 组件。它永远不可能和组件同步——面板改了组件没改，或者反过来，两边都"看起来对"。

### 3.3 修补是点状，不是类状（同类 bug 复发）

`component-fidelity-checklist.md` 记了 `Button` 三档高度"被 1px 边框撑成 46"——这是盒模型类问题。
但同一个类在 `ListCard.vue:31` 仍然存在：

    .list-card__add { width: 100%; ... border: 1px solid #E5E6EB; }

`width:100%` + `border` + 没有 `box-sizing: border-box` → 实际宽度比内容宽 2px，溢出卡片的 12px padding。
修了一个实例，没有修这一类，所以它必然在别处复发。

### 3.4 一次提交交付整包

334 modules / 44 个 `.vue` 落在同一个 commit。后果：任何偏差都无法定位"是哪一步引入的"，复盘只能把核对表重跑一遍——这次复盘就是这么来的。
粒度粗不是省事，是把定位成本推给未来。

### 3.5 范围漂移

10-06 裁决"先搭组件库，不先做业务页面"。实际 `src/pages/` 已有 10 个页面文件，`SpecialPageView.vue` 单个 65 处裸 hex、8 处 Node ID。
页面层没有走"逐属性核对"流程（清单第三节里一条页面记录都没有），所以**页面是偏差密度最高的地方，也是最没有验收记录的地方**。

### 3.6 验收对象可能不是源码

`dist/` 已提交进模板包（287KB CSS / 375KB JS），且落后 4 个源文件（`MemberSelectionFlow` / `Tag` / `SpecialPagesPreview` / `SecurityDetailPage`）。
谁跑 `dist` 预览，看到的就不是当前代码。反向也一样：改了源码没 build，以为"已经修好了"。

补充一条：状态用自然语言记（`pending` 写在注释和文档里，5 个文件含该词），机器不可查——所以"22 个组件全 pending"是设计的必然结果，不是执行不力。

## 四、一句话根因

**问题不在"AI 看不准"，在于流程没有闸门、事实源分裂，于是每一轮都在重新回答已经回答过的问题。**

你们把"知识"沉淀得很好（这一套文档是这次能复盘的前提），但知识没有变成**门禁**；同一组数值有五个副本，改一处不保证其余同步；交付粒度太粗，导致偏差只能事后逐项核对——而逐项核对又是人工的，于是回到第一条。

## 五、重来一次：5 个改动（按投入产出排序）

**1. 把三条硬约束变成会失败的命令（半天）**
`lint` 扫 `src/`：裸 hex ≠ 0 → 失败；`line-height` 非 px → 失败；`border` 无 `box-sizing` → 失败；组件无 Node ID 注释 → 失败。
现状 721 / 2 / ? / 22 会立刻全部报出来。**先做到"新增代码不加重"，再谈清理存量。**

**2. 单一事实源（1 天）**
`spec.json` 由 Figma 节点生成（相对坐标 + 真实字段），`theme.css` 从它派生，`DesignSpecPanel.vue` 只渲染 spec.json、删掉那 157 个裸 hex。
补丁规则"冲突时以此为准"应该消失，而不是再加一条。

**3. 验收最小闭环（1 天）**
每个验收元素加 `data-spec="<组件>.<元素>"`，跑 `box_check`（±1px）+ `diff_pixels`（≤0.5%）。
这一步把清单第四节的"尚未逐属性核对（15 个组件）"从"取决于人有没有时间"变成"跑一次就有数字"。

**4. 提交粒度（0 成本，习惯）**
一个组件一个 commit，commit message 带 Node ID 与偏差数。4 条改动就让 3.4 不再复发。

**5. 状态机外置（半天）**
`registry.json` 存 22 个组件的 `status: pending|confirmed` + `verifiedAt` + `gates` 三项结果。文档只渲染它。否则 pending 永远是 pending。
