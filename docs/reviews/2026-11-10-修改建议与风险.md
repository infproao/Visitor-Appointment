# 修改建议与风险清单（基于 2026-11-10 实测）

> 前一份：`docs/reviews/2026-11-10-构建过程复盘.md`（问题诊断）
> 本文：怎么改、什么顺序、每步会踩到什么。

---

## 一、执行顺序总表

| 阶段 | 内容 | 工期 | 视觉变化 | 可回滚 | 风险 |
|---|---|---|---|---|---|
| S0 | 固化基线数字，不改代码 | 2h | 无 | — | 低 |
| S1 | lint 接入，只拦新增 | 半天 | 无 | 删脚本即可 | 低 |
| S2 | 颜色 1:1 映射 token | 1–2 天 | **必须为 0** | 单 commit revert | **中高** |
| S3 | 修 3 处盒模型 + 加规则 | 半天 | 轻微 | 单 commit revert | 中 |
| S4 | DesignSpecPanel 单源化 | 1 天 | 面板不变 | revert | **高** |
| S5 | 字体：先探测后替换 | 探测半天 / 替换另排 | **全量重算** | 基线作废 | **最高** |
| S6 | 提交粒度 + dist 口径 | 0 | 无 | — | 低 |

顺序不能变的原因：S0 没有基线就没法判断 S2 是修好了还是改坏了；S4 必须在 S2 之后（token 层先立起来，面板才有东西可读）；S5 必须最后（换字体会让前面所有像素基线失效）。

---

## 二、逐项建议

### S0 固化基线（零风险，但必须最先做）

产出一份 `baseline.json`：裸 hex 721 / 唯一色 65 / 近似色对 13 / 无 Node ID 组件 22 / 盒模型风险块 20 / 字体声明 187 / 无 webfont。

**风险**：基线一旦被当成"允许保留的豁免"，就变成永久豁免，半年后又长回 2000 处。
**缓解**：基线带生成日期 + 只允许下降；规则写成"总数不得超过基线，且新增文件不得违规"，而不是"豁免名单"。豁免名单会腐烂，阈值不会。

### S1 lint 只拦新增（半天）

`package.json` 目前只有 `dev/build/preview`，没有任何检查入口——这是"约束不生效"的直接原因。加 `npm run gate`。

**风险 1**：727 处存量硬拦 → 第一次提交就红一片 → 团队关掉规则。
**缓解**：`--baseline baseline.json`，只报"超出基线的增量"。

**风险 2**：误报会毁掉信任。已知三类必须显式豁免：
- `theme.css`（token 定义处本身就该有值）
- `DesignSpecPanel.vue`（展示用的色块，S4 之后应改为读 json）
- `.svg` 里的 `fill=`（导出资产，不该改）
**缓解**：豁免白名单写进脚本，且在 README 注明"豁免只有这三类，加第四类要有理由"。

**风险 3**：裸 px 规则对 Figma 还原项目过严——设计值是 px，写 px 是正常的。
**缓解**：px 只作为**警告**不阻塞；阻塞项只留"裸 hex / 非 px 行高 / 无 box-sizing 的 border + 尺寸"这三条。否则规则会被当成噪音。

### S2 颜色 1:1 映射（中高风险）

**做法**：先从 65 个唯一值生成 `--c-<语义或序号>`，机械替换，**一次不合并**。替换前后跑像素比对，要求 0 变化。

**风险 1（最容易出事）**：13 组近似色被"顺手合并"。`F2F3F5`(52) / `F5F5F5`(4) / `F4F5F8`(2) / `F1F1F2`(1) 看着像同一个灰，但那 4 处 `F5F5F5` 可能是另一种语义（如示例区底色）。合并 = 设计决策，不是工程决策。
**缓解**：S2 只做 1:1，近似值合并单独立项，逐组找设计确认。判据：合并前后像素 diff 必须为 0，否则就是改了视觉。

**风险 2**：变量定义位置。写在 scoped 样式里，兄弟组件拿不到。
**缓解**：全部定义在 `:root`（theme.css），组件只引用。

**风险 3**：替换会漏。`rgba()`、`linear-gradient`、`box-shadow` 里的色值、`-webkit-text-fill-color` 都是裸 hex 的不同形态。
**缓解**：替换用 AST 或至少四条正则分别覆盖；替换后重跑 lint，裸 hex 必须归零。

**风险 4**：Vant 内部。改组件里的 hex 不影响 Vant 组件内部渲染，会变成"Hermes 一套色、Vant 一套色"。
**缓解**：同一步把 33 个 `--van-*` 对齐到新 token（它们本来就是 Vant 的入口），并用 pixel diff 验证 Vant 区域。

### S3 盒模型（中风险）

**做法**：只改明确出问题的 3 处 —— `ListCard.vue:31`（`width:100%` + border）、`MemberSelectionFlow` 的输入行、`Tag.vue` 三档 min-height；同时加规则"尺寸 + border + 无 box-sizing"报警，覆盖剩下 17 块。

**风险 1（这条最容易踩）**：直接上全局 `*, *::before, *::after { box-sizing: border-box }`。
实测有 **20 个规则块**同时有 `height/min-height` 和 `padding` 且没写 box-sizing。全局切换会让它们的可用内容高缩水（例：`MemberSelectionFlow` 的 `min-height:76px; padding:10px 0` → 内容区从 76 变成 56）。这是大面积位移，不是修 bug。
**缓解**：禁做全局切换。要么逐块改并逐块 diff，要么把全局切换当成独立项目（需要全量回归）。

**风险 2**：只改 3 处 = 又变成点状修补（复盘第三节 3.3 的同一个坑）。
**缓解**：3 处是"止血"，规则是"止血带"——没有规则的 3 处修复等于没修。

### S4 DesignSpecPanel 单源化（高风险）

**风险 1（顺序陷阱）**：先删 157 个 hex，再建 spec.json。结果是验收面板先变空/变错，而它是当前唯一的可视化验收基准——基准消失，后面所有"通过"都无意义。
**缓解**：必须"先生成 spec.json 并与现有 157 个值逐项对齐，确认无差异后再切换渲染"，切换后保留一次 diff 截图作为证据。

**风险 2**：spec.json 只能表达 Figma 里有的值。而你们的验收面板里有大量**非 Figma 值**：叠层偏移 12px、Button 红橙绿 neutral 四色、五色禁用色、DatePicker（无节点，van-calendar）。
**缓解**：spec 条目必须带 `source: "figma" | "decided" | "screenshot"`。缺这个字段，切换后这些已裁决的值会从面板里消失，等于把人工裁决记录抹掉。

**风险 3**：面板改为读 json 后，它和真实组件的偏差不再肉眼可见——因为面板显示的是 spec，不是渲染结果。
**缓解**：面板保留"spec 值 / 组件实测值 / 差值"三列。否则它从"验收工具"退化成"文档展示"。

### S5 字体（最高风险，单独排期）

现状：**187 处 `"PingFang SC"`，全工程 0 个字体文件，index.html 无外链**。所有"±1px 通过"都是在装有 PingFang 的机器上量的。

**风险 1**：部署端（泰国/越南，Android/Windows/kiosk）没有 PingFang → fallback 到 sans-serif → 字宽变 → 换行位置变 → 整列高度变。这是**线上必炸、本地看不出**的一类。
**缓解**：先做探测（半天，零风险）：验收时断言 `getComputedStyle().fontFamily` 实际命中的字体，不命中就报警。Mac 上永远通过不影响现状，换机器立刻暴露。

**风险 2**：真换 webfont = 所有宽度重算，历史所有像素基线作废，之前"通过"的结论全部失效。
**缓解**：单独排期；换之前冻结一次基线存档；换之后全量重跑并重新签收。不要在 S2/S3 期间夹带。

**风险 3**：webfont 加载期间（FOUT）量出来的是 fallback 尺寸。
**缓解**：验收脚本必须 `document.fonts.ready` 后再量（collect_metrics.js 已有此断言）。

### S6 交付纪律（低风险）

**提交粒度**：一个组件一个 commit，message 带 Node ID + 偏差数。这是唯一能让"偏差定位"从"重跑核对表"变成"看 git log"的办法。

**dist**：`visitor-skill-package.bin` 与仓库里的 `.zip` **md5 相同**（bc5f8dc9…），说明它是有意的离线交付物，不能直接删。
**风险**：删掉会破坏"不能跑 npm 的环境"这条交付路径；保留则继续产生"验收对象不是源码"。
**缓解**：build 后写 `dist/build-info.json`（commit hash + 构建时间 + 源文件数），README 标注"dist 仅供离线预览，验收以 src 为准"；落后者在 CI 里报警而不阻塞。

## 三、明确不要做的四件事

1. **不要全局切 `border-box`**：20 个尺寸+padding 块会同时变，那不是修 bug，是一次无基线的大改版。
2. **不要合并近似色**：13 组里至少 `F5F5F5` 那 4 处需要设计确认语义，工程侧无权合并。
3. **不要先删 DesignSpecPanel 的 157 个值**：它是当前唯一验收基准，先删等于拆掉脚手架再盖楼。
4. **不要在字体未锁的情况下把 pixel diff 当唯一判据**：diff 结果不可移植，本机 0% 不代表交付端 0%。

---

## 四、回滚与基线纪律

- 每个阶段独立 commit，S2 / S3 / S4 各自可单独 revert。
- S2 的验收判据只有一条：**替换前后像素 diff 必须为 0**。不为 0 就说明机械替换改到了视觉，回滚重做。
- S5 完成后旧基线整体作废，新基线重新签收，不要混用。
- 每阶段结束把 `baseline.json` 的数字贴进 commit message，形成可追溯的下降曲线。
